8085 Microprocessor Architecture

SIM and RIM Instructions Overview

In the 8085 microprocessor, SIM (Set Interrupt Mask) and RIM (Read Interrupt Mask) are 1-byte, multi-purpose instructions used primarily for interrupt control and serial communication. Both instructions interact directly with the Accumulator (Register A) to send or receive control bits.

SIM: Set Interrupt Mask (Opcode: 30H)

The SIM instruction is used to enable/disable (mask) hardware interrupts (RST 5.5, 6.5, 7.5) and to output serial data. You must load the desired bit pattern into the accumulator before executing SIM.

RIM: Read Interrupt Mask (Opcode: 20H)

The RIM instruction is used to check the current status of the interrupt system and read incoming serial data. Executing RIM loads a status byte into the accumulator for the programmer to read.

Key Differences

  • Direction: SIM sends data from the accumulator to control registers; RIM reads from the registers into the accumulator.
  • Control vs. Monitoring: SIM is used to change settings (like masking an interrupt), while RIM is used to check settings (like seeing if an interrupt is pending).
  • Serial Port: SIM uses the SOD (Serial Output Data) pin; RIM uses the SID (Serial Input Data) pin.
8085 Microprocessor Interrupt Architecture

8085 Interrupt System

An interrupt in the 8085 microprocessor is an asynchronous signal initiated by an external peripheral or an internal instruction that temporarily suspends the main program execution and redirects the core processor to an Interrupt Service Routine (ISR).

Vectored vs. Non-Vectored

Vectored Interrupts: Automatically force the Program Counter (PC) to branch to a predefined, fixed memory vector destination address.

Non-Vectored Interrupts: The microprocessor does not provide a fixed address. The peripheral hardware must monitor the INTA (Interrupt Acknowledge) cycle and place a valid branching instruction (typically RST 0 – RST 7 or a 3-byte CALL) onto the data bus.

Maskable vs. Non-Maskable

Maskable: Can be blocked, disabled, or ignored by executing software flags such as DI (Disable Interrupt) or configuring specific register configurations using the SIM instruction.

Non-Maskable: Cannot be suppressed by any software instruction. TRAP is the sole non-maskable hardware pin. It bypasses all software locks for critical exceptions like catastrophic system power failure routines.

8259 PIC Internal Architecture

8259 Programmable Interrupt Controller

Internal Architecture & Register Bit Configurations

The Intel 8259 Programmable Interrupt Controller (PIC) is a hardware support chip designed to expand the interrupt capabilities of microprocessors like the 8085 and 8086. It manages up to 8 vectored hardware interrupts, routes them via a single interrupt pin (INTR), handles vector addresses, and implements configurable priority modes.

Register Bit-Field Assignments

Interrupt Request Register

Stores all the external interrupt request levels (IR₀ to IR₇) waiting to be serviced by the microprocessor.

Interrupt Mask Register

An 8-bit programmable register used to mask (disable) or unmask individual interrupt channels dynamically using program configurations.

In-Service Register

Tracks which specific interrupt levels have been accepted and are currently being executed by the microprocessor's Interrupt Service Routine (ISR).

8259A Core Operations and Handshake Sequence

8259A Programmable Interrupt Controller Operations

A functional breakdown of priority resolution, End-Of-Interrupt mechanics, and CPU handshake sequences.

The Core 7-Step Interrupt Handshake Sequence

When external peripheral hardware interfaces assert an interrupt request, the 8259A and the system CPU coordinate execution using the following chronological stages:

  1. Request Assertion: One or more external lines (IR0 through IR7) are pulled high by peripheral hardware modules.
  2. Registration: The 8259A registers and locks these active physical requests into its internal Interrupt Request Register (IRR).
  3. Priority Evaluation: The internal Priority Resolver evaluates the logged bits against active masks stored in the Interrupt Mask Register (IMR) to determine the highest priority unmasked request.
  4. CPU Signaling: The 8259A drives its physical INTR output pin high to notify the microprocessor.
  5. Acknowledge Loop: The CPU completes its active instruction cycle and responds by executing an active-low /INTA (Interrupt Acknowledge) pulse back to the 8259A.
  6. State Shift: Upon receiving the /INTA pulse edge, the 8259A sets the corresponding tracking bit inside the In-Service Register (ISR) and clears the respective request bit from the IRR.
  7. Vector Delivery:
    • 8085 Microprocessor Mode: The CPU fires two subsequent /INTA pulses. The 8259A responds by broadcasting a 3-byte CALL instruction opcode (CDH) alongside the 16-bit target ISR memory address over the data bus lines.
    • 8086 Microprocessor Mode: The CPU fires one single secondary /INTA pulse. The 8259A reacts by placing an 8-bit interrupt type index vector directly onto the data bus channel.
Direct Memory Access (DMA) and Intel 8257 Specification

Direct Memory Access (DMA)

A data transfer technique that allows peripheral devices to transfer data directly to or from the system memory without continuous intervention from the CPU. This bypasses the CPU completely during data transfers, significantly increasing system speed and efficiency.

The DMA Operational Concept

During normal operation, the CPU acts as the data transfer intermediary. This process consumes multiple clock cycles. Under a DMA configuration, control over the system buses shifts dynamically through the following stages:

  • Request: The peripheral device requests a DMA transfer by pulling the controller's request line high.
  • Hold: The DMA controller sends a HOLD request signal to the CPU.
  • Acknowledge: The CPU completes its current instruction, puts its data, address, and control buses into a high-impedance state (floating), and returns a HLDA (Hold Acknowledge) signal to the DMA controller.
  • Transfer: The DMA controller takes control of the system buses and manages the high-speed data transfer directly between the memory and the peripheral.
  • Release: Once the transfer is complete, the DMA controller drops the HOLD line, returning bus control back to the CPU.
